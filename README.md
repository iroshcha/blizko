# Близко

Личный зашифрованный чат Android / Windows и веб-клиент для iPhone. Нативное iOS-приложение пока не разрабатывается.

## Веб-приложение для iPhone

Открыть [Близко в Safari](https://ample-raven-6363.ru.tuna.am/web/) → «Поделиться» → «На экран Домой» → запустить с иконки и создать профиль. Веб-версия 0.2 поддерживает зашифрованную переписку с Android/Windows 0.3.0+, QR из фото, историю, черновики, очередь и зашифрованные резервные копии. Для переписки обменяйтесь QR в обе стороны.

Уведомления включаются в настройках установленного веб-приложения (iOS 16.4+). В них нет текста и имени собеседника. Сообщения загружаются при открытии. При очистке данных браузера профиль теряется без резервной копии. [Сборка, тесты и ограничения](web/README.md).

## 0.3.0 — серверный транспорт

Весь обмен проходит через домашний компьютер: `https://ample-raven-6363.ru.tuna.am/` → Tuna → `Blizko.Server.exe` на `DESKTOP-ADG1PFE`. Прямых соединений, поиска публичных ретрансляторов и встроенного iroh больше нет. Сервер должен быть включён. В версии 0.3.1 зашифрованные пакеты хранятся на сервере до семи дней: собеседники могут открывать приложения в разное время. «На сервере» означает сохранённый пакет; «Доставлено» — проверенное подтверждение получателя. При недоступном сервере очередь остаётся на устройстве отправителя.

Одно WSS-соединение на устройство передаёт пакеты и ответы без HTTP-опроса. Вход доказывает владение ключом Ed25519 через случайный одноразовый вызов; каждый пакет и ответ подписаны устройством. Содержимое сообщений и подтверждения сохраняют NaCl box и привязку к ключам из QR. Сервер видит идентификаторы маршрутизации, время и объём трафика, но не имеет ключей сообщений. История на сервере не хранится; отдельная диагностика описана ниже. Это собственный протокол без Double Ratchet и независимого криптографического аудита.

Ключи, QR, контакты, история, черновики и очередь от 0.2.4/0.2.5 сохраняются. Поле хранилища `irohSeed` оставлено только для совместимости: теперь оно содержит ключ идентификации нового транспорта. **Обе стороны разговора должны обновиться до 0.3.0.** Старые клиенты не понимают новый серверный протокол. Не удаляйте приложение перед установкой обновления.

11 октября 2026 домашний сервер обновлён через восстановленный SSH. Проверены HTTPS, доставка Windows через Tuna и управляемый перезапуск сервера. Порядок перехода и откат — [core/server/README.md](core/server/README.md).

## Интерфейс и данные

Версия **0.2.4** добавляет зашифрованные черновики по контактам, локальные счётчики непрочитанных, переход к первому непрочитанному, даты и поиск по всей переписке. Долгое нажатие на Android / правая кнопка мыши на Windows открывает копирование, повтор и отмену неотправленного сообщения. В версии 0.3.1 отмена доступна до первой попытки передачи: переданный серверу пакет может быть получен позже. Уже полученное сообщение не удаляется. Повтор использует прежний ID для защиты от дублирования. Неподходящие пакеты отклоняются до помещения в очередь; прежние повреждённые пакеты явно показываются как неотправленные и не блокируют следующие сообщения.

Хранилище 0.2.4 использует формат 5: зашифрованный журнал состава записей, атомарный указатель и восстанавливаемое намерение записи. Потеря метаданных или ожидаемой записи обнаруживается, новая личность рядом со старой историей не создаётся. Успешное подтверждение отправляется после завершения сохранения. При обновлении формат 4 мигрирует с сохранением ключей, контактов и очереди; уже утраченные до миграции записи нельзя обнаружить по отсутствовавшему в старом формате журналу. После обновления не устанавливайте поверх 0.2.3 или более старую версию. Очистка выполняется в фоне с прогрессом и отменой, сохраняет ожидающие сообщения; прерванная очистка оставляет уже очищенные строки очищенными.

Проверка связи показывает, выключен ли локальный приём, отсутствует ли сетевое подключение, установлена ли связь с сервером и отвечает ли собеседник. Отсутствие ответа само по себе не доказывает, что собеседник выключил приём. Проверка отменяется пользователем и не блокирует статус, отправку и выключение приёма.

## Сборка и проверки

Нужны Go, для Windows — .NET Framework 4.x и ZXing.Net, для Android — JDK 17, Android SDK/NDK 28.2.13676358, Gradle 8.11.1 и gomobile/gobind. Rust больше не нужен.

- `scripts/build-windows.ps1`: Windows-приложение и `dist/Blizko.Server.exe`; `scripts/package-windows.ps1` пакует строгий набор файлов обновления, `-Modern` исключает старую DLL.
- `scripts/build-android.ps1`: ARM64/x86_64 Android; задайте `ANDROID_HOME`, `ANDROID_NDK_HOME`, `JAVA_HOME` при внешней установке SDK.
- `cd core; go test ./...; go vet ./...`; с C-компилятором — `go test -race ./...`.
- `scripts/test-windows-local.ps1`: настоящий локальный сервер и два Windows-процесса, двусторонняя доставка, очередь, перезапуск, сохранение QR.
- `scripts/test-windows-updates.ps1 -OutputDirectory <новая-папка>`: подписи обновлений, откат и восстановление после сбоя, старый и новый состав архива.
- Android instrumentation: запустить локальный сервер на 3340, `adb reverse tcp:3340 tcp:3340`, установить debug и androidTest APK, затем `adb shell am instrument -w -r ru.blizko.chat.test/ru.blizko.chat.QrAndUpdateTest`. Изолированный тестовый эмулятор использует loopback, а не домашний сервер.

Внешний сервер требует HTTPS с действительным сертификатом. HTTP допускается только на буквальном loopback-адресе для локальных проверок. `BLIZKO_SERVER_URL` переопределяет адрес при запуске; старое имя `BLIZKO_RELAY_URL` пока поддержано. Указанный сервер единственный, запасного публичного адреса нет.

CI: `.github/workflows/android.yml` и `windows.yml`. Проверки эмулятора не заменяют тесты физических телефонов и измерение расхода аккумулятора.

## Обновления

Windows проверяет подписанный RSA/SHA-256 манифест раз в 6 часов, пока работает, и по кнопке. Архив проверяется до установки, история в `%LOCALAPPDATA%\Blizko` не заменяется. Android использует существующую подпись APK; новый ключ создавать нельзя.

Переходный Windows-архив 0.3.0 содержит **неиспользуемую** DLL iroh и её лицензию из проверенного архива 0.2.5: установленный обновлятор 0.2.5 требует ровно 12 файлов. Новый движок DLL не загружает. Обновлятор 0.3.0 принимает также новый строгий набор из 10 файлов, поэтому следующий пакет сможет обходиться без этих двух файлов. `scripts/windows-compat.ps1` проверяет SHA-256 исходного архива; Rust для этого не собирается.

Публиковать 0.3.0 следует после проверки домашнего сервера и обоих клиентов. Последний GitHub Release должен сохранять `android-update.json` и `windows-update.json`, даже при обновлении одной платформы. Закрытые ключи подписи не входят в репозиторий или CI.

## Диагностика Android

Отключённый по умолчанию технический журнал: экран, заряд, Doze, сеть, жизнь службы, наблюдение входящих и очереди отправки без содержимого. События переживают перезапуск и отправляются порциями на собственный сервер после настройки. Приватный код создаётся на сервере; его нет в APK. [Устройство, ограничения и проверка](core/diagnostics/README.md).

Лицензии используемых библиотек: `THIRD_PARTY_NOTICES.txt`, `windows/ZXING_NET_NOTICE.txt`.
