# Близко

Личный чат Android / iPhone / Windows со **встроенным iroh 1.1.0**. Аккаунт Tailscale, API-ключ, отдельный VPN, собственный сервер и постоянно включённый компьютер не нужны.

Версия **0.2.0** — прототип для проверки связи на реальных телефонах. Бесплатные публичные ретрансляторы iroh предназначены для разработки и личных проектов, имеют ограничения скорости и не гарантируют доступность. Работу в конкретных российских сетях нужно проверять отдельно.

## Обновление и подключение

1. Установите новый APK **поверх прежней версии**, не удаляя приложение. Сохраняются идентификатор приложения, сертификат подписи, ключи сообщений, история, контакты и очередь. Миграция создаёт отдельный ключ iroh; старые сетевые адреса больше не используются. Возвращаться к версии 0.1.4 после миграции нельзя: она не понимает новый формат хранилища.
2. Обновите оба телефона и включите приём. Дождитесь «Подключено · iroh».
3. **Заново обменяйтесь QR в обе стороны**: «Мой QR» → картинка; «Контакт» → камера или QR из фото → имя. Новый QR обновляет существующий контакт без потери переписки. Старые коды `blizko:2:` отклоняются; новые используют `blizko:3:`.
4. Отправьте сообщение. «Доставлено» появляется только после проверки зашифрованного подтверждения сохранения на телефоне получателя. Недоставленное остаётся на устройстве отправителя.

Общий Wi-Fi не нужен; интернет нужен обоим устройствам. Для начального теста используйте разные сети без VPN и открытые приложения. «Проверить связь с собеседником» проверяет ответ другого приложения и наличие вашего контакта.

«Настройки соединения» → **«Только через ретранслятор»** отключает прямые IP-маршруты внутри iroh для диагностики. Обычный режим разрешает прямое соединение и автоматический переход на ретранслятор.

## Android

Android 8+, ARM64; x86_64 включён для эмулятора. В фоне работает foreground service с постоянным уведомлением и кнопкой выключения приёма. Ограничения батареи и принудительная остановка могут задержать доставку.

«Обновления» использует GitHub Releases. Проверяются HTTPS, размер, SHA-256, идентификатор приложения, версия и сертификат подписи APK. Ключ подписи остаётся локальным. CI-артефакт имеет другой отладочный сертификат: публикуемый APK собирается локально с прежним ключом.

Канал: https://github.com/iroshcha/blizko/releases/latest/download/android-update.json.

## Windows

Windows 10/11 x64: полностью распакуйте `Blizko-Windows-x64.zip` и запустите `Blizko.exe`. Регистрация и вход в аккаунт Windows/Microsoft или сетевого сервиса в приложении не нужны. Ключи создаются автоматически. Требуется .NET Framework 4.8; приложение запускается без прав администратора.

Приём включается при открытии приложения. Добавьте QR с телефона через «+ Контакт» → картинка или скопированный код, укажите имя; «Мой QR» позволяет сохранить картинку для импорта на телефоне. Обмен нужен в обе стороны. Windows имеет отдельную идентичность; история с телефона не синхронизируется. Совместим тот же протокол и QR `blizko:3:` версии 0.2.0.

Сборка Windows тестовая. Локально проверены обмен двух независимых процессов, кириллица/эмодзи, оба режима соединения и доставка очереди после перезапуска через локальный ретранслятор. Защищённый транспорт прошёл отдельную проверку с локальным TLS. В текущей сети сборки публичные ретрансляторы подключаются, но сообщения не получают подтверждения доставки. Проверки с физическими Android/iPhone ещё нет.

Enter отправляет сообщение, Shift+Enter добавляет строку. Закрытие/сворачивание окна оставляет приём в системном трее. Двойной щелчок возвращает окно, «Выйти» в меню значка останавливает ядро. Во время сна или выключения компьютера приём невозможен.

История находится в `%LOCALAPPDATA%\Blizko` под AES-256-GCM. Ключ автоматически защищается встроенным Windows DPAPI без отдельного входа или пароля; перенос хранилища в другой профиль/на другой компьютер не поддерживается. Два ядра не могут одновременно изменять одну историю. При обновлении заменяют файлы приложения, сохраняя папку данных.

Сборка: Go 1.27.2, Rust 1.99.0 с Windows x64 toolchain и .NET Framework 4.8. ZXing.Net 0.16.11 (`lib/net40/zxing.dll`) — в `.tools/zxing` либо через параметр `-ZxingDll`. `scripts/build-windows.ps1` собирает DLL iroh, Go-ядро, WPF-интерфейс и запускает тесты. MSVC toolchain требует Visual C++ build tools; GNU — совместимый MinGW GCC. Готовая программа не требует Go, Rust или GCC. `.github/workflows/windows.yml` создаёт архив для Windows, проверяет QR, сохранение ключей, реальную доставку и перезапуск двух независимых процессов.

## iPhone без своего Mac

macOS runner GitHub Actions собирает неподписанный IPA с тем же Go/Rust-ядром. Для публичного репозитория используются стандартные бесплатные runners. Установка — SideStore/Sideloadly с собственным Apple Account. Бесплатная подпись действует 7 дней и требует обновления. Для сохранения истории обновляйте приложение поверх прежнего с тем же Apple Account и bundle ID.

**Постоянного фонового приёма на iPhone нет:** iOS может приостановить приложение. Для доставки откройте оба приложения. Нет APNs-сервера, скрытого аудио или VoIP-трюков. Сборка не заменяет проверку установки, камеры и переписки на физическом iPhone.

## Данные и ограничения

- История, контакты, очередь, ключи сообщений и ключ iroh хранятся локально под AES-256-GCM. Ключ хранилища защищён Android Keystore / iOS Keychain / Windows DPAPI. Облачные резервные копии отключены.
- Rust iroh встроен в Go-ядро через C ABI. Нет локального HTTP-сервера или VPN-процесса; HTTP-типы Go используются только как внутренний адаптер очереди к запросам iroh.
- Используются публичное обнаружение адресов и ретрансляторы n0. Они пересылают зашифрованные пакеты; история и очередь сообщений остаются на телефонах. Сетевая инфраструктура видит метаданные соединений. Это не архитектура без каких-либо сторонних серверов.
- Каждый пакет проверяется по идентификатору iroh из QR и закреплённому ключу сообщения. NaCl box дополнительно защищает сообщения и подтверждения. Это собственный протокол прототипа без Double Ratchet и независимого аудита.
- До 100 контактов, 100 ожидающих и 2000 сообщений. Нет групп, файлов, звонков, синхронизации и восстановления ключей. Удаление приложения удаляет историю.

## Сборка и проверки

Actions → **Build iroh native transport** (`.github/workflows/iroh-native.yml`) собирает Rust для Linux, Android ARM64/x86_64, iOS ARM64, проверяет Go-ядро и собирает APK/IPA. Учётные записи сетевого сервиса не нужны.

Локальная Android-сборка: библиотеки из артефакта `iroh-native-ubuntu-latest` в `core/iroh/lib`, затем `scripts/build-android.ps1`. Можно взять `mobile.aar` из CI и выполнить локальный `:app:assembleDebug`, чтобы использовать прежний сертификат. iOS: библиотеки `aarch64-apple-ios` + `bash scripts/build-ios.sh` на macOS. Симулятор iOS отдельно не собирается.

```sh
cd core
go test ./mobile
go vet ./mobile
# На Linux с собранной core/iroh/lib/host:
go test -race -tags=iroh ./mobile
BLIZKO_NETWORK_SMOKE=1 go test -tags=iroh -run TestIrohRealRelayDeliveryAndRestart -v ./mobile
```

Без тега `iroh` сетевой запуск возвращает явную ошибку: это режим модульных тестов. Мобильные сборки всегда используют `iroh`.

Android instrumentation `ru.blizko.chat.QrAndUpdateTest` проверяет кнопку приёма, QR из изображения, подтверждение контакта, верификацию APK и обмен двух независимых ядер через публичный iroh: обычный режим, принудительный relay, очередь после отключения. Один эмулятор не доказывает связь между физическими телефонами разных операторов.

Лицензии Go/Android: `THIRD_PARTY_NOTICES.txt`; Rust: `IROH_NOTICES.txt` внутри обеих сборок. Архив исходников содержит только закоммиченные файлы.

Для Windows `scripts/test-windows-local.ps1` скачивает официальный ретранслятор 1.3.0 с проверкой SHA-256, запускает его только на `127.0.0.1:3340`, проверяет готовую сборку и останавливает сервер. Проверка публичной сети: `Blizko.exe --network-test <новая-папка-теста>`. Для собственного сервера можно задать `BLIZKO_RELAY_URL`; внешний сервер требует HTTPS с действительным сертификатом, HTTP допускается только для loopback. Без переменной используются стандартные ретрансляторы n0.
