# Близко — интерфейс веб-приложения

Зафиксировано 17 октября 2026 для веб-версии 0.2.1. Это уточнение существующего
светлого интерфейса, а не смена бренда. Область: `web/src/`.

## Назначение

Личная переписка на iPhone, Android и Windows через собственный сервер.
Основной сценарий веба — добавить знакомого по QR, написать сообщение,
понять состояние доставки. Цвет, типографика и движение обслуживают этот сценарий.
Публичные маркетинговые страницы не входят в этот проход.

## Визуальная система

- Один системный шрифт с кириллицей, без сетевой загрузки. Текст сообщений 16px/1.55,
  контакты 15px, служебные подписи 12–13px, заголовок чата 17px.
- Основной текст `#203b36`, вторичный `#596c65`, акцент `#146555`.
  Полотно `#f3f5f2`, белые сообщения и окна, боковая панель `#fafbf8`.
  Исходящие `#dfecdf`, выбранный контакт `#e5eee7`.
- Радиус контролов 12px, сообщений 16px с различимым направлением,
  окон 20px. Тень используется только для поверхностей над содержимым.
- Боковая панель 320px, на промежуточной ширине 292px. До 700px список и чат
  становятся последовательными экранами. Сообщение ограничено 640px.
- Управляющие иконки — собственные SVG 24×24 со штрихом 1.8.
  Эмодзи в пользовательских сообщениях остаются обычным содержимым.
- Контролы от 44px, поля 16px для Safari, видимый клавиатурный фокус,
  подписи окон, метки полей, подсказки и ошибки рядом с действием.

## Движение

| Событие | Реализация | Назначение |
| --- | --- | --- |
| Нажатие кнопки | мгновенное scale(.97), возврат 140ms | Отзыв на действие |
| Открытие и закрытие окна | 200ms, opacity + 6px/scale(.98), парный backdrop | Сохранить контекст |
| Новое видимое сообщение | 180ms, 6px/opacity | Показать поступление |
| Копирование | подпись на исходной кнопке на 2.2s | Подтвердить действие на месте |

Кривая `cubic-bezier(.22,1,.36,1)`. Нет циклической декоративной анимации,
прокрутки с подменой поведения, задержки фокуса, анимации восстановленной истории
или stagger-эффектов списка. При `prefers-reduced-motion: reduce` пространственное
движение отключено, цветовая обратная связь сохранена. Старые Safari без discrete
transitions открывают окна сразу штатным способом. Hover применяется только к мыши.

## Применённые навыки и решения

- [Impeccable](https://github.com/pbakaus/impeccable/tree/6af45ac9a5eb8792f033d3242f52e99812fd91fa/.agents/skills/impeccable),
  версия навыка 4.6.0: Operate, polish, craft-floor. Убраны декоративные надписи
  над заголовками, согласованы контролы, контраст, сетка и состояния.
- [Taste Skill](https://github.com/Leonxlnx/taste-skill/tree/f624f37a8c650b9cc550253104925efe4c8de246/skills/taste-skill)
  установлен; текущая v2 прямо исключает app screens. Для этой поверхности прочитана
  и применена [универсальная v1](https://github.com/Leonxlnx/taste-skill/tree/f624f37a8c650b9cc550253104925efe4c8de246/skills/taste-skill-v1):
  одна палитра, согласованные отступы, полноценные состояния, SVG вместо символов.
  Маркетинговые требования к изображениям, магнитным кнопкам и бесконечным эффектам
  не перенесены в часто используемую переписку; здесь приоритет у Operate и UI Animation.
- [UI Animation](https://github.com/mblode/agent-skills/tree/81d0af2f6d4b32d791fb26caa82b17603ef4d807/skills/ui-animation):
  purpose/frequency, парные переходы, немедленный фокус, feedback на месте,
  reduced motion, transform/opacity. Выбран как профильный Animation Skill для UI.

Существующая архитектура JavaScript сохранена; дополнительных runtime-зависимостей
нет. Ранее использованные материалы Build Your Own X по сохранению DOM и состоянию
указаны в `web/README.md`; этот проход не создаёт новое ядро интерфейса.

## Проверка

`web/tests/browser.mjs`: Chromium и WebKit, 320/390/768/1280px, native dialog focus,
быстрые повторные открытия, reduced motion, безопасный изолированный clipboard stub,
ручное выделение кода при отказе clipboard, прежние interop/storage/offline сценарии.
Снимки и результаты текущего прохода: `.tools/web-design-021/`.
Механический Impeccable detect по изменённым HTML/CSS вернул `[]`.
Физический iPhone и системная клавиатура устройства ещё требуют ручной проверки.
