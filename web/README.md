# Близко — веб-клиент 0.2.1

В 0.2.1 уточнён дизайн по Impeccable, Taste Skill и UI Animation: компактная шапка,
единые цвета и SVG-иконки, адаптивный первый запуск, короткие переходы окон и новых
сообщений, подтверждение копирования на кнопке. Исправлен возврат клавиатурного
фокуса после закрытия окна. Система и источники: [DESIGN.md](../DESIGN.md).
Пространственное движение отключается по системной настройке reduced motion.
Проверки выполняются на 320, 390, 768 и 1280px. Сборка объединена с серверной очередью и Web Push из native 0.3.1. Уведомления включаются только по кнопке в настройках; текст переписки в push не передаётся.

PWA для Safari/iPhone и современных браузеров. Текущий адрес: `https://ample-raven-6363.a.tuna.free/web/`.

17 октября 2026 сервер обновлён до 0.2.1 с сохранением mailbox/Web Push из native 0.3.1. Tuna перевела бесплатный поддомен с `ru.tuna.am` на `a.tuna.free`; старый адрес отклонён провайдером на бесплатном тарифе. Новый origin требует восстановления браузерного профиля из резервной копии; серверные зашифрованные очереди и ключи уведомлений сохранены. В Android/Windows адрес сервера можно изменить в настройках без замены личности.

## Пользование

1. На iPhone открыть ссылку в Safari. На разовой странице бесплатного Tuna нажать «Посетить». Затем «Поделиться» → «На экран Домой».
2. Запустить с иконки, ввести имя. Настройку лучше выполнять уже в установленном приложении: хранилища вкладки Safari и установленного приложения могут отличаться.
3. Добавить контакт в три шага: получить QR (фото или вставка `blizko:3:…`), сохранить имя, показать свой QR и проверить связь. Проверку можно отложить, контакт уже сохранён. Нативные собеседники — Android/Windows **0.3.0+**.
4. При желании включить уведомления в настройках. На iPhone это доступно в установленном на главный экран приложении. Если получатель не в сети, сервер сохраняет зашифрованный пакет, а приложение получает его при подключении. «На сервере» ещё не означает «Доставлено».
5. Настройки → резервная копия: зашифрованный JSON с паролем минимум 10 символов. Восстановление доступно на стартовом экране до создания профиля. Закрыть старую копию профиля, чтобы две установки не переподключали одну личность.

Очередь до 200 сообщений, видимая история до 2000, до 100 контактов, хранилище до 8 МиБ. В настройках есть очистка истории с отдельным подтверждением: неотправленные сообщения (в том числе отменённые), черновики, контакты и ключи сохраняются. Для уже принятых сообщений остаются компактные идентификаторы и хеши: потерянное подтверждение можно отправить повторно, не возвращая удалённый текст. Общий предел записей, включая такие отметки, — 40 000; предел размера 8 МиБ также сохраняется. Входящие при заполнении не подтверждаются, исходящие не теряются молча. Автоматического удаления истории нет. Импорт истории из нативных приложений не реализован; веб-клиент создаёт собственный контакт.

## Протокол и хранение

Пересмотр очередей и хранения по материалам Build Your Own X: [отчёт от 16 октября 2026](architecture-review-2026-10-16.txt). В версии 0.2.0 очередь продвигается после завершения доставки, по кругу между контактами, с максимум четырьмя активными доставками и интервалом не менее 150 мс между стартами. Ошибки сохраняют паузу перед повтором; возвращение отменённого сообщения также проверяет лимит очереди. Развёртывание этой сборки выполняется отдельно.

## Интерфейс 0.2.0

Переписка обновляется по идентификаторам сообщений. Подтверждения меняют только статус, а новые входящие не сбивают выделение текста и чтение старой истории. Для перехода к новым сообщениям появляется отдельная кнопка. Контакты обновляются без пересоздания кнопок и сортируются по последней активности.

`src/ui-state.js` содержит только временное состояние интерфейса: выбранный чат, поиск, отправку, результат проверки связи и шаг добавления контакта. Запоздавший результат проверки другого открытия чата отбрасывается. Постоянные данные остаются в Chat/Vault. `src/conversation-view.js` отвечает за сохранение DOM-узлов, прокрутки и выделения.

Поле сообщения растёт до 160 px, Enter оставляет перенос строки, Ctrl/⌘+Enter отправляет. Пустой текст, превышение 4000 байт UTF-8 и повторная отправка во время сохранения блокируются. Ошибка сохранения оставляет набранный текст и объяснение рядом с полем. Офлайн-отправка сохраняет прежнюю очередь. Подписи показывают подключение к серверу, а не выдуманный онлайн собеседника; «Доставлено» означает сохранение, а не прочтение. Остановить повторы можно только до передачи пакета на отправку.

Использованные ориентиры из Build Your Own X: [Build your own React](https://pomb.us/build-your-own-react/) — сохранение узлов при обновлении; [Build yourself a Redux](https://zapier.com/blog/how-to-build-redux/) — явные переходы состояния. Реализация остаётся на JavaScript без React/Redux и без новых зависимостей.

Проверки интерфейса входят в `npm test` и `web/tests/browser.mjs`: мастер контакта, ошибки QR, многострочный ввод, лимит UTF-8, сочетание клавиш, сохранение узлов/выделения/прокрутки, кнопка новых сообщений, ошибка отправки, мобильный и широкий экран. Проверка клавиатуры и установки на настоящем iPhone по-прежнему необходима.

Совместимые с общим Go-ядром Ed25519 challenge/login и подписи каждого пакета/ответа, NaCl box (Curve25519 + XSalsa20 + Poly1305), QR v3, envelope/payload v2. Canonical JSON учитывает HTML-escaping Go и U+2028/U+2029. Доставка подтверждается только после окончания транзакции IndexedDB; ответ брокера `unavailable` означает только повтор. Собеседники закреплены по обоим публичным ключам. При включённом `-mailbox` сервер временно хранит зашифрованные пакеты и подтверждения доставки. Содержимое доступно только участникам переписки. Статус «На сервере» отличается от подтверждения «Доставлено».

IndexedDB содержит AES-GCM шифротекст профиля/контактов/истории и неэкспортируемый CryptoKey. Это не парольная блокировка: код того же origin способен использовать ключ. Резервная копия отдельно шифруется AES-GCM, PBKDF2-SHA256/310000, случайные соль и nonce. Очистка данных сайта удаляет ключи и историю; копия необходима для восстановления. Private Browsing не предназначен для постоянного хранения.

Web Locks не допускает две активные вкладки с одним хранилищем. Мутации сериализованы, состояние заменяется после commit. Номер ревизии проверяется и меняется в той же транзакции, поэтому запоздавшая запись старой вкладки не перезапишет новую историю. На ошибке чтения существующее хранилище не перезаписывается. Пользовательские строки выводятся через textContent, CSP запрещает внешние скрипты, inline script и embedding; зависимости поставляются внутри EXE. Origin проверяется точно по явному флагу, Host/Forwarded не используются для доверия. Доверие к коду веб-приложения зависит от сервера и HTTPS/Tuna: изменив отдаваемый JS, оператор этой инфраструктуры мог бы получить ключи. Это ограничение веб-доставки кода.

Service Worker кэширует только оболочку `/web/`, не сообщения, QR, ключи или диагностику. Новая версия ожидает нажатия «Обновить приложение» в настройках. Профиль IndexedDB сохраняется. Идентификатор кэша — хеш сборки. Постоянный HTTPS origin необходим для сохранения профиля и установленного приложения.

## Сборка и тесты

```powershell
cd web
npm ci --ignore-scripts
npm run build
npm test
cd ../core
go test ./...
go build -trimpath -o ../.tools/Blizko.WebTestServer.exe ./server
go build -trimpath -o ../.tools/Blizko.WebTestPeer.exe ./webapp/testpeer
cd ..
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.tools/pw-browsers"
node web/node_modules/playwright/cli.js install chromium webkit
node web/tests/browser.mjs
```

Go сервер встраивает `core/webapp/assets`, поэтому обычная сборка Android/Windows не требует Node. Для изменения веб-кода обязательно выполнить `npm run build`. Lockfile закрепляет версии и integrity npm-пакетов. Исходные SVG/PNG значки находятся в `web/src`; PNG — растровые варианты собственного SVG.

Браузерные тесты создают изолированные профили и настоящий клиент общего Go-ядра; проверяют двустороннюю Unicode-переписку, шифрованные receipts, отказ IndexedDB без ложного ack, QR из фото, offline/reload/draft, второй tab, backup/restore, offline shell и ширину 390px. Снимки и отчёт: `.tools/web-checks`. WebKit на компьютере не заменяет проверку установки и поведения на физическом iPhone.

## Развёртывание

EXE запускается с `-web-origin https://ample-raven-6363.a.tuna.free`. Без флага native-клиенты продолжают работать, браузерный Origin отклоняется. `/web/` обслуживается тем же процессом и туннелем, что `/blizko/v1/socket` и диагностика. `scripts/server-runtime.ps1` берёт hostname из существующей настройки Tuna и передаёт точный origin, без изменения авторизации Tuna. Перед заменой EXE/Server.ps1 сохранить копии, остановить существующее задание, заменить, запустить; при провале health/interop вернуть оба файла. Код диагностики, журналы, конфиг Tuna и задание не заменяются.
