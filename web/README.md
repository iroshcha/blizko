# Близко — веб-клиент 0.1

PWA для Safari/iPhone и современных браузеров. Адрес после развёртывания: `https://ample-raven-6363.ru.tuna.am/web/`.

## Пользование

1. На iPhone открыть ссылку в Safari. На разовой странице бесплатного Tuna нажать «Посетить». Затем «Поделиться» → «На экран Домой».
2. Запустить с иконки, ввести имя. Настройку лучше выполнять уже в установленном приложении: хранилища вкладки Safari и установленного приложения могут отличаться.
3. Добавить контакт: фотография QR, выбор изображения или вставка `blizko:3:…`. Обменять QR в обе стороны с Android/Windows **0.3.0+**.
4. Оставить приложение открытым для приёма. Веб-клиент 0.1 не имеет Web Push, не обещает приём в фоне или при погашенном экране. Очередь отправляется при следующем открытии и доступности собеседника.
5. Настройки → резервная копия: зашифрованный JSON с паролем минимум 10 символов. Восстановление доступно на стартовом экране до создания профиля. Закрыть старую копию профиля, чтобы две установки не переподключали одну личность.

Очередь до 200 сообщений, история до 2000, до 100 контактов, хранилище до 8 МиБ. Ограничения явные: входящие при заполнении не подтверждаются, исходящие не теряются молча. Автоматического удаления истории нет. Импорт истории из нативных приложений не реализован; веб-клиент создаёт собственный контакт.

## Протокол и хранение

Совместимые с общим Go-ядром Ed25519 challenge/login и подписи каждого пакета/ответа, NaCl box (Curve25519 + XSalsa20 + Poly1305), QR v3, envelope/payload v2. Canonical JSON учитывает HTML-escaping Go и U+2028/U+2029. Доставка подтверждается только после окончания транзакции IndexedDB; ответ брокера `unavailable` означает только повтор. Собеседники закреплены по обоим публичным ключам. Сервер не сохраняет переписку.

IndexedDB содержит AES-GCM шифротекст профиля/контактов/истории и неэкспортируемый CryptoKey. Это не парольная блокировка: код того же origin способен использовать ключ. Резервная копия отдельно шифруется AES-GCM, PBKDF2-SHA256/310000, случайные соль и nonce. Очистка данных сайта удаляет ключи и историю; копия необходима для восстановления. Private Browsing не предназначен для постоянного хранения.

Web Locks не допускает две активные вкладки с одним хранилищем. Мутации сериализованы, состояние заменяется после commit. Номер ревизии проверяется и меняется в той же транзакции, поэтому запоздавшая запись старой вкладки не перезапишет новую историю. На ошибке чтения существующее хранилище не перезаписывается. Пользовательские строки выводятся через textContent, CSP запрещает внешние скрипты, inline script и embedding; зависимости поставляются внутри EXE. Origin проверяется точно по явному флагу, Host/Forwarded не используются для доверия. Доверие к коду веб-приложения зависит от сервера и HTTPS/Tuna: изменив отдаваемый JS, оператор этой инфраструктуры мог бы получить ключи. Это ограничение веб-доставки кода.

Service Worker кэширует только оболочку `/web/`, не сообщения, QR, ключи или диагностику. Новая версия ожидает нажатия «Обновить приложение» в настройках. Профиль IndexedDB сохраняется. Идентификатор кэша — хеш сборки. Постоянный HTTPS origin необходим для сохранения профиля и установленного приложения.

## Сборка и тесты

```powershell
cd web
npm ci --ignore-scripts
npm run build
npm test
cd ../core
go test ./...
go build -trimpath -o ../.tools/Blizko.WebTestServer.exe ./server
go build -trimpath -o ../.tools/Blizko.WebTestPeer.exe ./webapp/testpeer
cd ..
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.tools/pw-browsers"
node web/node_modules/playwright/cli.js install chromium webkit
node web/tests/browser.mjs
```

Go сервер встраивает `core/webapp/assets`, поэтому обычная сборка Android/Windows не требует Node. Для изменения веб-кода обязательно выполнить `npm run build`. Lockfile закрепляет версии и integrity npm-пакетов. Исходные SVG/PNG значки находятся в `web/src`; PNG — растровые варианты собственного SVG.

Браузерные тесты создают изолированные профили и настоящий клиент общего Go-ядра; проверяют двустороннюю Unicode-переписку, шифрованные receipts, отказ IndexedDB без ложного ack, QR из фото, offline/reload/draft, второй tab, backup/restore, offline shell и ширину 390px. Снимки и отчёт: `.tools/web-checks`. WebKit на компьютере не заменяет проверку установки и поведения на физическом iPhone.

## Развёртывание

EXE запускается с `-web-origin https://ample-raven-6363.ru.tuna.am`. Без флага native-клиенты продолжают работать, браузерный Origin отклоняется. `/web/` обслуживается тем же процессом и туннелем, что `/blizko/v1/socket` и диагностика. `scripts/server-runtime.ps1` берёт hostname из существующей настройки Tuna и передаёт точный origin, без изменения авторизации Tuna. Перед заменой EXE/Server.ps1 сохранить копии, остановить существующее задание, заменить, запустить; при провале health/interop вернуть оба файла. Код диагностики, журналы, конфиг Tuna и задание не заменяются.
