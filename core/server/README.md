# Сервер Близко 0.3.0

Один Go-процесс, без iroh и Rust. Слушает только `127.0.0.1:3340`. Tuna завершает HTTPS и проксирует HTTP/WebSocket на этот адрес. Домен, аккаунт и стоимость существующего туннеля не меняются. Чат работает без отдельной учётной записи Windows пользователя приложения.

Маршруты: `/blizko/v1/socket` — двусторонний WebSocket; `/healthz` — HTTP 204; `/blizko-diagnostics/v1` — необязательная диагностика с отдельным bearer-кодом. Другие пути закрыты. Ни маршруты, ни чат не сохраняются в серверные журналы.

Лимиты: 128 подключений с учётом незавершённых входов, 10 секунд на вход, 48 000 байт на кадр, 20 000 байт на полезный пакет, очередь 8 кадров на получателя, 20 кадров/сек на подключение с запасом 40. Дубликат подключения одного ключа заменяет прежнее. Переполненная очередь возвращает подсказку повторить; она никогда не считается подтверждением доставки. Аутентификация доказывает ключ устройства, но не является списком разрешённых пользователей сервера.

## Подготовка и переход

11 октября 2026 сервер развёрнут на домашнем ПК. Старый запуск сохранён в `D:\Blizko-Server\.installation\before-030-20261011-123500`. Проверены HTTPS, двусторонняя доставка Windows, очередь, диагностический POST и управляемый перезапуск. Задание `Blizko-Home-Relay` сохранило включённый запуск при загрузке Windows и повтор при сбое через минуту; внутри теперь запускаются `Blizko.Server.exe` и Tuna. Реальная перезагрузка Windows не выполнялась.

1. Собрать: в `core` выполнить `go build -trimpath -ldflags="-s -w" -o ../dist/Blizko.Server.exe ./server`.
2. После восстановления доступа прочитать фактический `Server.ps1`, задание `Blizko-Home-Relay` и параметры Tuna; сохранить резервные копии. Не заменять существующую настройку без проверки её состава.
3. Разместить сервер и `scripts/start-server.ps1` рядом в отдельном каталоге. Проверить новый EXE на свободном порту (например `-listen 127.0.0.1:3342`) и `/healthz`.
4. Согласовать переход обоих клиентов: старый iroh-протокол несовместим с 0.3.0. В управляемом запуске заменить только процесс старого реле на новый сервер 3340. Запускной скрипт опционально включает диагностику и создаёт приватный каталог/код; для чата достаточно запустить EXE без `-token`.
5. Сохранить существующий единственный процесс Tuna, домен, отключённый инспектор и цель `http://127.0.0.1:3340`. Не создавать второй туннель с тем же доменом.
6. Проверить HTTPS `/healthz`, два обновлённых клиента, очередь при выключенном получателе, обрыв сети, перезапуск сервера, автозапуск после перезагрузки ПК. Только после этого публиковать подписанные обновления обеих платформ.

Откат: вернуть сохранённый запуск iroh и прежние клиентские бинарники 0.2.4/0.2.5, не удаляя данные. Формат хранилища остаётся 5, ключи не меняются. Держать старые пакеты до успешного завершения проверки. Новые клиенты не смогут общаться через старое реле, старые — через новый сервер.

## Проверка локально

`go test ./...` проверяет подмену подписей, одноразовый вход, лимиты URL, отмену, перезапуск брокера и клиентов, устойчивую очередь и архив диагностики. `scripts/test-windows-local.ps1` использует настоящий EXE. Android-эмулятор подключается через `adb reverse tcp:3340 tcp:3340`.

Скорость Интернета и расход аккумулятора этим не измеряются. Для сравнения нужны одинаковые устройства, сеть и сценарий на старой/новой версиях. При недоступном домашнем сервере автоматического обходного маршрута нет.
