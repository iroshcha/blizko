# Диагностика Android и шлюз домашнего ретранслятора

Сбор выключен по умолчанию. В приложении: **Диагностика фоновой работы**, HTTPS-адрес и код доступа с собственного сервера. Код открывает только запись технических событий; ключи переписки не используются. После выключения удаляются локальная очередь, код и расписание отправки. Уже принятые события удаляются на сервере по сроку хранения.

Собираются фиксированные поля: время UTC, elapsedRealtime и uptime, вид события, уровень заряда/питание, экран, Doze, экономия, исключение из оптимизации, ограничение фоновой работы, тип/доступность сети, состояние службы/приёма и последняя известная доступность ядра. Android 11+ сообщает числовую причину предыдущего завершения процесса, если она есть. Не собираются описание ошибки/стек, logcat, тексты сообщений, имена/ID контактов, QR, IP/SSID и ключи. Случайный ID диагностики меняется при повторном включении.

Фиксируются также факт наблюдения нового входящего сообщения и постановка исходящего в очередь, без содержимого, размеров и адресата. Наблюдение входящего берётся при очередном опросе работающего приёма (обычно до 5 секунд); оно может опоздать при заморозке процесса. `send_queued` не означает доставку.

Это наблюдение, а не точный измеритель расхода энергии. `online` — последнее наблюдение ядра, не подтверждение доставки. Отсутствие событий нельзя считать доказательством убийства процесса энергосбережением. На части устройств причина завершения неточна или отсутствует. Принудительная остановка пользователем блокирует работу до следующего запуска.

## Хранение и отправка

- Телефон: AtomicFile в `noBackupFilesDir`, максимум 512 событий / 1 МиБ; очередь переживает остановку процесса. События старше 7 дней удаляются при следующем обращении к очереди. Во время сна приложение ради очистки не пробуждается.
- Запись только при событиях, изменении состояния связи, паузе более 2 минут и раз в 15 минут уже работающего приёма. Нет дополнительного таймера пробуждения или WakeLock.
- JobScheduler: период 1 час, требуется сеть, Android вправе отложить работу. Одна порция до 64 событий / 64 КиБ; ограничение запроса 45 секунд, повторы с задержкой. Кнопка отправки запрашивает отдельную сетевую задачу, не обходит Doze.
- Только HTTPS, стандартная проверка сертификата/имени, без перехода по redirect. Очередь удаляется только после HTTP 204. При потере ответа возможен повтор: при анализе учитывать `(device, events.id)` как ключ события.
- Сервер: фиксированная схема, bearer-код 256 бит, до 4 одновременных загрузок и 120 запросов в минуту, JSONL до 16 файлов по 2 МиБ. Код и HTTP-заголовки не пишутся в журнал. Публичного чтения нет. Срок по времени приёма — 7 дней; очистка при запуске и каждый час (на выключенном сервере — при следующем запуске). Промежуточный файл очистки может кратковременно занимать ещё до 2 МиБ.
- На Windows доступ к каталогу `diagnostics-private` ограничивает запускной скрипт текущим пользователем и SYSTEM. Администратор ОС по-прежнему может получить доступ. На сервере журнал хранится без шифрования; канал HTTPS завершается у Tuna, как и подключение чата. Диагностика не использует сквозное шифрование чата.

## Развёртывание без второго туннеля

Сначала прочитать фактический `Server.ps1` и задание `Blizko-Home-Relay` на сервере; не заменять их непроверенным шаблоном. 11 октября 2026 SSH восстановлен, сервер диагностики развёрнут вместе с новым транспортом. Проверен авторизованный синтетический POST через публичный HTTPS; журнал на пользовательских телефонах остаётся выключенным до включения владельцем.

1. В `core`: `go test ./diagnostics`, затем `go build -trimpath -ldflags="-s -w" -o ../dist/Blizko.Server.exe ./server`.
2. Скопировать EXE и `scripts/start-server.ps1` в новый серверный каталог. Скрипт создаёт приватный код и журналы, запускает сервер только на `127.0.0.1:3340`.
3. Полный порядок переключения старого iroh-сервера и клиентов, проверка автозапуска и откат — [../server/README.md](../server/README.md). Чат и диагностика обслуживаются одним процессом и одним туннелем Tuna.
4. Проверить `/healthz`, зашифрованную переписку двух новых клиентов и HTTPS POST диагностики. Не публиковать клиентский релиз до проверки сервера.
5. При сбое вернуть сохранённый старый запуск и прежние клиенты, не удаляя данные.
6. Код из `diagnostics-private/access-code.txt` ввести на тестовом телефоне. Не включать его в APK, репозиторий, QR контакта, URL или публичный выпуск. Читать журнал через имеющийся SSH-доступ, не открывать каталог наружу.

## Проверка энергосбережения

Эмулятор: instrumentation `adb shell am instrument -w -r -e diagnostics true ru.blizko.chat.test/ru.blizko.chat.QrAndUpdateTest` проверяет очередь, отключение, схему и подтверждение отправки с тестовым HTTPS-транспортом. Серверные тесты проверяют авторизацию, запись/отказ диска, ротацию и удаление старых строк в смешанном файле. Дополнительно `scripts/test-windows-local.ps1` проверяет настоящую зашифрованную переписку и перезапуск двух Windows-процессов через новый сервер; этот тест прошёл локально. Тестовые подмены транспорта существуют только в androidTest.

Для отдельного тестового эмулятора сначала включить диагностику и приём, отключить оптимизационное исключение, если оно было, затем:

```text
adb shell dumpsys battery unplug
adb shell input keyevent 223
adb shell dumpsys deviceidle force-idle
adb shell dumpsys deviceidle get deep
# С другого тестового устройства отправить сообщение; сравнить время доставки после выхода.
adb shell dumpsys deviceidle unforce
adb shell dumpsys battery reset
adb shell input keyevent 224
```

Восстановление системных настроек обязательно и при ошибке теста. Дополнительно проверить выключенную сеть, возврат сети, повторный запуск и принудительную остановку. Настоящий телефон: отметить начало теста, погасить экран на 30–60 минут, отправить с Windows сообщения с известным временем, затем открыть приложение и отправить журнал. Повторить с экономией включённой/выключенной при одинаковых условиях. Сравнивать доставку и паузы; для оценки расхода нужны более длительные сопоставимые прогоны на физическом телефоне.

Справка Android: [Doze и App Standby](https://developer.android.com/training/monitoring-device-state/doze-standby), [ApplicationExitInfo](https://developer.android.com/reference/android/app/ApplicationExitInfo).
